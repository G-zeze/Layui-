## 3. 学习特点

- **怎么学进去：** 先看结构 → 逐层拆开 → 自己用 `console.log` 验证。多个新概念同时出现时容易建立不起因果，要拆开一层一层来。
- **最在意"这个值从哪来"：** 每出现一个新参数（`obj`、`d`、`res`、`list`），先说清是谁传进来的。
- **对没学过的内容很敏感：** 布置任务或让他查语法之前，必须先核对是否已经学过（查速查笔记）。
- **笔记格式：** 喜欢"代码 → 结构树 → 一句话规则"；注释风格像他自己写的"方法名：做什么，第一个参数是……"。
- **听不懂会直说**（"啥都不知道""讲义太少，要我自己蒙"）。原因通常是先讲了术语、没先说这一步为了解决什么，或没说清代码写在哪、名字对应哪个。
- **追问质量高：** "先画空表有什么用""fetch 官方定义是什么""为什么刷新又回来"。
- **节奏：** 愿意跳过非核心的收尾（如校验），尽快进入能看到效果的下一步。

## 4. 常犯的错

| 类型 | 例子 |

| 文件位置 | `main.py` 放进讲义文件夹；直接改 13 号存档 |
| 照抄示例 / 名字混用 | 照抄示例名 `courses`；页面 JS 里用 `main.py` 的函数名 `stu` |

排错已养成习惯：F12 Console 红字 → 看行号 → 对照速查笔记 8.1。

## 5. 教学策略（据此决定怎么教）

1. 新内容先说"这一步解决什么"，再给代码，术语放最后。
2. 讲解要短，但讲义要能照着做：写在哪、分几步、示例名 ↔ 他的名字、执行顺序、常见红字都写清。
3. 他亲手写代码；出错先给"位置 + 类型"，他说"你帮我看"再直接指出。
4. 每次只推进一个可验证任务；他在电脑前时一次给 3～6 个小步骤。
5. 每节学完都在速查笔记追加一节。
6. 讲 JS / Layui 不用 Python 类比；讲 FastAPI 可以拿他学过的 Layui 写法对照（如 `table.on` 登记 ↔ `@app.get` 登记）。

## 6. 当前缺口

1. 函数与回调：能用，但写新的嵌套回调（如 `then` 链）时还要看示例。
2. 前后端的边界：哪些名字在服务器上、哪些在页面上，刚开始分清。
3. 异步：知道"`then` 里的最后执行"，还没学 `async/await`。
4. 后端：路径参数、请求体、校验、增删改、数据库都还没重学。
